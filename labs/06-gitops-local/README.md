# Lab 6 fallback: Managed Argo CD, GitOps, and local login

[Home](../../README.md) | [Previous: Lab 5](../05-persistent-volumes/README.md)

**Use this alternative when you do not have permission to create app
registrations in Microsoft Entra ID.** Azure subscription permissions do not
automatically grant Entra directory permissions. This exercise does not require
you to create an Entra app registration, service principal, security group,
consent grant, or SSO-app federated credential. The [original Lab 6](../06-gitops/README.md) remains the
Entra SSO path; complete **one version, not both**.

**Goal:** Install Microsoft's managed Argo CD extension, sign in with a local
Argo CD account, deploy from your GitHub fork, and observe GitOps reconciliation.
This alternative does not teach Entra SSO, group claims, or group-based RBAC.

**Time:** 60-90 minutes. **Prerequisites:** the existing upgraded Lab 2 cluster
and Terraform state, completed earlier-lab settings, a public GitHub fork of
this repository, and a local Bash terminal and browser.
You still need Azure permissions to create a managed identity and its federated
credential, and to manage `Microsoft.KubernetesConfiguration/extensions`
(for example, Kubernetes Extension Contributor). Those Azure resource
permissions are separate from permission to create Entra app registrations.

**Lab-only security tradeoff:** This path uses the built-in local `admin`
account, which has unrestricted Argo CD administrator privileges, not the
original lab's project-scoped Entra role. Use only your own disposable training
cluster. Keep the UI behind a localhost port-forward; never expose it with an
Ingress, Gateway, public Service, or `--address 0.0.0.0`. Do not reuse a password
from another account.

No Argo CD CLI, second Helm installation, DNS name, or public TLS certificate
is needed. Labs 2-3's `demo` namespace and Lab 5's `storage-demo` remain
untouched; this exercise deploys into **`gitops-demo`**.

## What stays managed

Use the same Terraform root and state as Labs 2-5. Terraform still creates the
`Microsoft.ArgoCD` extension, its dedicated repo-server managed identity, and
the identity's federated credential. That managed identity is an Azure resource,
not an app registration you must create in Entra. A public GitHub repository
needs neither a GitHub token nor an Azure data role.

Local login replaces only the human SSO path. Terraform omits the Entra OIDC
and group mapping settings and enables Argo CD's local administrator account.
The password is generated by Argo CD in Kubernetes, not supplied in tfvars or
stored in Git. Redis HA remains disabled because the shared cluster has only
two application nodes; the two system nodes are reserved for critical add-ons.
This is not a production HA or access-control design.

## 1. Reconnect and check the existing cluster

Verify the subscription, cluster context, and node capacity before installing
anything. Run commands from the repository root.

<details>
<summary>Solution: reconnect and verify capacity</summary>

```bash
source .workshop/env.sh
az account set --subscription "$SUBSCRIPTION_ID"
export RESOURCE_GROUP=$(terraform -chdir=infrastructure output -raw resource_group_name)
export AKS_NAME=$(terraform -chdir=infrastructure output -raw cluster_name)
az aks get-credentials --resource-group "$RESOURCE_GROUP" --name "$AKS_NAME" --overwrite-existing
kubectl config current-context
kubectl get nodes
kubectl get pods --all-namespaces
az extension add --name k8s-extension --upgrade
```

Keep the existing cluster, Terraform state, and Lab 5 PVC. Do not run
`terraform destroy` between labs. The cluster already has OIDC and Workload
Identity enabled.

An instructor should check the
[managed extension's current requirements](https://learn.microsoft.com/azure/azure-arc/kubernetes/tutorial-use-gitops-argocd)
before class. Use current configuration keys, not pre-1.0 preview examples.

</details>

## 2. Install the managed extension with local authentication

Enable the explicit fallback setting, preserving all earlier lab inputs and
the upgraded Kubernetes version.

<details>
<summary>Solution: enable the Terraform-managed local-login alternative</summary>

Add these settings to the existing `infrastructure/terraform.tfvars`, editing
any existing entries rather than duplicating them:

```hcl
enable_argocd             = true
argocd_local_auth_enabled = true
```

Leave `argocd_sso_client_id` and `argocd_group_object_id` unset; their defaults
are empty. Do not run the original Lab 6's Entra creation or federation commands.
The local-authentication setting defaults to `false`, so the original Lab 6
continues to require Entra SSO.

```bash
terraform -chdir=infrastructure init
terraform -chdir=infrastructure fmt -check
terraform -chdir=infrastructure validate
terraform -chdir=infrastructure plan -out=argocd.tfplan
```

Expect **three additions**: the managed identity, its federated credential, and
the managed extension. No cluster replacement or unrelated changes are expected.
Inspect the extension settings: local admin enabled, Service type `ClusterIP`,
localhost UI URL, Redis HA disabled, and no Entra OIDC configuration.

```bash
terraform -chdir=infrastructure apply argocd.tfplan
az k8s-extension show --resource-group "$RESOURCE_GROUP" \
  --cluster-name "$AKS_NAME" --cluster-type managedClusters --name argocd \
  --query '{state:provisioningState,version:version}' --output table
kubectl -n argocd get deployments,statefulsets,pods,services
kubectl -n argocd rollout status deployment/argocd-server --timeout=600s
kubectl -n argocd get configmap argocd-cm -o yaml
```

Confirm `admin.enabled` is `"true"` and no Entra `oidc.config` is configured.
Terraform owns the installation settings; fix them in Terraform, then review
and apply a new plan. Do not install a second Argo CD or directly edit
extension-owned ConfigMaps.

`server.insecure=true` makes the server use HTTP. That is acceptable only for
this localhost exercise: port-forward carries traffic over the authenticated
Kubernetes connection and the Service is not publicly exposed.

</details>

## 3. Bootstrap the project and sample Application

Reuse the original lab's manifests, pointing **both** repository URLs at your
public fork. Keep the `apps/demo` path and `gitops-demo` destination.

<details>
<summary>Solution: prepare the same GitOps demo without Entra dependencies</summary>

```bash
cp labs/06-gitops/project.yaml .workshop/project.yaml
cp labs/06-gitops/application.yaml .workshop/application.yaml
printf 'Use this repository URL in BOTH files: https://github.com/%s/aksintro.git\n' "$GITHUB_USERNAME"
```

Open `.workshop/project.yaml` and `.workshop/application.yaml` in your editor.
Set the AppProject's `spec.sourceRepos` entry and the Application's
`spec.source.repoURL` to the printed URL. Verify that your fork contains
`apps/demo/manifest.yaml` on `main`.

```bash
kubectl apply -f .workshop/project.yaml
kubectl apply -f .workshop/application.yaml
kubectl -n argocd get applications
```

The [AppProject](../06-gitops/project.yaml) restricts this application's
repository, destination, and resource types. It does **not** restrict the local
`admin` account's ability to change projects or other Argo CD settings.
The [Application](../06-gitops/application.yaml) starts with manual sync,
without a cascading-deletion finalizer. `CreateNamespace=true` creates the
destination on sync; an initial `OutOfSync`/missing-resource state is expected.

Only `apps/demo` is reconciled. The Application and AppProject themselves are
bootstrapped with `kubectl`, not an app-of-apps.

</details>

## 4. Sign in with the local account and change its password

Start the UI on the same machine as your browser, then retrieve the generated
initial password. Treat the displayed value as a secret.

<details>
<summary>Solution: localhost UI and local admin login</summary>

In a second local terminal:

```bash
kubectl config current-context
kubectl -n argocd port-forward service/argocd-server 8080:80
```

Leave it running. In your main terminal, retrieve the initial password:

```bash
kubectl -n argocd get secret argocd-initial-admin-secret \
  -o jsonpath='{.data.password}' | base64 --decode
printf '\n'
```

Open **http://localhost:8080** and sign in with username **`admin`** and the
displayed password. Use the username/password form, not Microsoft Entra login.
There is no Entra redirect URI or consent step.

In **User Info -> Update Password**, replace the initial password with a
unique lab password. Sign out and confirm that the new password works, then
delete the secret containing the now-obsolete initial password:

```bash
kubectl -n argocd delete secret argocd-initial-admin-secret
```

Do not delete `argocd-secret`, which holds the active password hash and other
server secrets. On resuming, use your changed password; the deleted initial
secret is no longer needed. Do not paste passwords into Git, tfvars, shared
terminal logs, or screenshots. No Argo CD CLI is required.

</details>

## 5. Perform a manual sync

Deploy the demo from Git, then compare its live status and response.

<details>
<summary>Solution: first sync and application verification</summary>

In Argo CD, select **aksintro-demo -> Sync**, inspect the resources, then
confirm **Sync**. Do not select pruning. Wait for **Synced** and **Healthy**.

In your main terminal:

```bash
kubectl -n gitops-demo rollout status deployment/demo --timeout=300s
kubectl -n gitops-demo get deployments,pods,services
kubectl -n argocd get application aksintro-demo \
  -o jsonpath='{.status.sync.status}{" "}{.status.health.status}{"\n"}'
```

In a third terminal:

```bash
kubectl -n gitops-demo port-forward service/demo 8082:80
```

From your main terminal:

```bash
curl http://localhost:8082
```

Expect `Hello from AKS! Version 1`, independently of the earlier `demo` and
persistent-storage workloads.

</details>

## 6. Make a change in Git

In **your fork** on GitHub, edit `apps/demo/manifest.yaml` on `main`, changing
`Hello from AKS! Version 1` to `Hello from AKS! Version 2`. Commit through
GitHub's web editor.

<details>
<summary>Solution: inspect the Git diff and sync the new revision</summary>

Select **Refresh** in Argo CD. Expect **OutOfSync**. Inspect **Diff** and confirm
that the demo container's `-text` argument changed, then select **Sync**.

```bash
kubectl -n gitops-demo rollout status deployment/demo --timeout=300s
kubectl -n argocd get application aksintro-demo \
  -o jsonpath='{.status.sync.revision}{"\n"}'
```

Compare the reported revision to your Git commit. Restart the demo port-forward
if its pod was replaced, then:

```bash
curl http://localhost:8082
```

Expect `Hello from AKS! Version 2`. Pull the commit into your local clone with
`git pull --ff-only` when convenient; do not overwrite uncommitted changes.

</details>

## 7. Enable automatic sync and observe self-healing

Keep pruning disabled. Change the live replica count and observe Git's desired
value win.

<details>
<summary>Solution: automatic reconciliation and controlled drift</summary>

```bash
kubectl -n argocd patch application aksintro-demo --type merge --patch \
  '{"spec":{"syncPolicy":{"automated":{"prune":false,"selfHeal":true}}}}'
kubectl -n gitops-demo scale deployment demo --replicas=3
kubectl -n gitops-demo get deployment demo --watch
```

Argo CD restores **1** replica from Git. Press `Ctrl+C` after observing it,
then verify:

```bash
kubectl -n gitops-demo get deployment demo -o jsonpath='{.spec.replicas}{"\n"}'
kubectl -n argocd get application aksintro-demo \
  -o jsonpath='{.status.sync.status}{" "}{.status.health.status}{"\n"}'
```

Expect `1` and eventually `Synced Healthy`. If reconciliation is too fast to
see, inspect the UI's sync history and events.

This patch updates the live bootstrap Application. Add the same automated-sync
settings to `.workshop/application.yaml` if you want to reproduce them.
The checked-in sample intentionally starts with manual sync.

Pruning deletes tracked resources removed from Git; self-healing restores
changed resources. They are different features. Do not point this application
at Lab 5's PVCs or experiment with pruning persistent storage.

</details>

## Checkpoint

You can sign in with a local Argo CD account, deploy from your fork, trace the
running application to a Git commit, and observe self-healing, without creating
an Entra app registration. Lab 5's persistent workload remains untouched.
Unlike the original Lab 6, this does not demonstrate Entra SSO or scoped
human-access RBAC.

## Troubleshooting

| Symptom | What to inspect or fix |
| --- | --- |
| Terraform asks for SSO/group IDs | Confirm `argocd_local_auth_enabled = true` is saved in the existing tfvars; do not invent Entra IDs |
| Azure denies identity or extension creation | Ask the instructor for the required Azure resource permissions; local login bypasses only the Entra app-registration requirement |
| Extension is not `Succeeded` | Inspect extension error details, pod events, current region/version support, and installation permissions |
| Redis pods stay pending | Confirm `redis-ha.enabled=false`; the default HA layout needs more nodes |
| Port 8080 is already used | Use another local port, such as `8081:80`, and open that localhost port; this path has no SSO callback to update |
| Initial-password secret is missing | Wait for server readiness on a fresh install; after rotation/deletion, use your changed password instead |
| Local login fails or only SSO is offered | Verify `admin.enabled` and the Terraform local-auth setting; this alternative is intended instead of the original SSO lab, not as an in-place migration |
| Repository comparison fails | Check public fork visibility, both URLs, `main`, `apps/demo`, and outbound HTTPS to GitHub |
| Sync says resource/project not permitted | Check the project's allowlist, destination, and resource types; keep the `aksintro` project |
| Demo still serves Version 1 | Check the fetched Git revision, completed sync, Deployment rollout, and current port-forward |
| Drift is not corrected | Confirm `automated.selfHeal=true` and that you changed the `gitops-demo` deployment |

```bash
kubectl -n argocd get events --sort-by=.lastTimestamp
kubectl -n argocd logs deployment/argocd-server --tail=100
kubectl -n argocd describe application aksintro-demo
```

Do not share secret values in troubleshooting output.

deletion section if you created none; do not source `.workshop/entra.env` or
delete someone else's objects.
